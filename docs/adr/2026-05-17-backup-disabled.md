# ADR-0008: Backup Disabled for MVP

**Date:** 2026-05-17  
**Status:** Accepted  
**Deciders:** Engineering Team

## Context

Azure PostgreSQL Flexible Server requires a backup retention policy to be specified. The minimum retention period is 7 days. Geo-redundant backup storage doubles the effective backup cost. For the MVP phase, the database contains only synthetic sample data, development sessions, and test audit logs — no real user data, no financial records, and no regulatory obligations.

## Decision

Set `backup_retention_days = 7` (minimum) and disable geo-redundant backup (`geo_redundant_backup_enabled = false`) for the MVP PostgreSQL Flexible Server.

## Rationale

- **No irreplaceable data in MVP:** The database holds synthetic sample data generated by `scripts/generate_sample_data.py`. If the instance is lost, data can be regenerated with `make seed-all` (or `generate_sample_data.py` + `seed_db.py` + user/pricing seed scripts).
- **Cost optimization:** Geo-redundant backup storage roughly doubles backup costs. For a pre-production system with no SLA, this spend is not justified.
- **Reversible decision:** Re-enabling geo-redundant backup and extending retention requires a single Terraform variable change followed by `terraform apply`. No data migration is needed.
- **Trigger-based re-enable:** The decision to disable backup is conditional; explicit re-enable triggers are documented so the risk does not persist indefinitely.

## Trade-offs

- **Data loss risk:** If the PostgreSQL instance fails catastrophically before a point-in-time restore can recover it, all sessions, audit logs, and memories since the last backup are lost.
- **No cross-region recovery:** With geo-redundant backup disabled, a full Azure `eastus2` region outage would result in permanent data loss for the period since the last backup.
- **7-day window only:** Any data older than 7 days cannot be recovered via point-in-time restore. For production use cases, this window is insufficient.

## Consequences

- `terraform/shared/` sets `backup_retention_days = 7` and `geo_redundant_backup_enabled = false`.
- This setting is acceptable only while the database contains synthetic data and no real users or financial records.
- **Re-enable triggers (must act before any of these are true):**
  - Real user data or production decisions are written to the database.
  - A regulatory or compliance requirement applies (SOX, GDPR, etc.).
  - A disaster recovery SLA is established.
  - The project moves from MVP to production.
- When re-enabled, set `backup_retention_days = 35` and `geo_redundant_backup_enabled = true` in `infra/terraform/shared/`.
- The DESIGN.md risks table records this as an explicitly accepted risk for MVP.
