# DECISIONS.md

Lightweight daily log of key design decisions.

Historical decisions (2026-06-02 – 2026-06-03, P0–P23) archived at `docs/archive/v3/DECISIONS.md`.

| Date | Decision | Rationale |
|---|---|---|
| 2026-06-04 | Add Ollama as dev LLM provider (`LLM_PROVIDER=ollama`) | Eliminate Anthropic API costs during local development; qwen2.5-coder:7b runs comfortably on 8 GB RAM in WSL2. `LLMClient` protocol unchanged. ADR: `docs/adr/2026-06-04-ollama-local-llm-provider.md` |
| 2026-06-04 | Store prompt/response in `llm_usage` via optional `LLMUsage` fields | Enable post-hoc LLM call inspection without external services (no MLflow/Langfuse required). Additive nullable columns; `UsageWriter` signature unchanged. Covered by `ClaudeClient` and `OllamaClient`. |
| 2026-06-04 | S&OP MVP: add SupplyPlanningAgent, FinanceImpactAgent, InventoryAgent enhancement, SopAgent | Four new/enhanced domain agents to enable full S&OP cycle (demand→inventory→supply→finance→decision). SpecialistRole Literal widened with "supply_planning", "finance_impact", "sop" — additive, no existing code breaks. Revenue impact analysis deferred (no price table in schema). Supply tools use supply_orders table; finance tools use cost_master. ADR: docs/adr/2026-06-04-sop-specialist-roles.md |
| 2026-06-04 | Extend Demand Agent with 8 analysis tools (Data Analysis Layer) | Demand planning = data analysis, not just forecasting. Agent must answer "why", "is it temporary", "which customer", "is the forecast trustworthy" — not only "what is the forecast". 4 must-have: `profile_demand_data`, `analyze_demand_trend`, `evaluate_forecast_accuracy`, `detect_demand_anomalies`. 4 next-tier: `analyze_seasonality`, `analyze_demand_drivers`, `segment_demand`, `compare_demand_periods`. `Tool` protocol and SQL guardrail `ALLOWED_READ_TABLES` are unchanged; tools use direct parameterized `execute_read_query` calls. |
| 2026-06-05 | Adopt LangGraph as the agent execution control engine | LangGraph handles graph state, specialist invocation order and parallelism, tool execution flow, HITL `interrupt()`/resume, checkpointing, and working-context accumulation. Long-term memory (PostgreSQL + pgvector), Skill Registry, Tool Gateway, artifact storage, queue/worker, and frontend live outside LangGraph — it manages flow, not storage or business logic. |
| 2026-06-05 | Specialist Agent subdivision rationale (context window, reuse, parallelism) | Delegating domain reads to Specialists prevents the Control Agent's context from filling with all-domain data simultaneously. Each Specialist encapsulates stable domain logic (days-on-hand, safety stock, OTIF) without re-explaining it per prompt. Parallel specialist runs (Demand + Inventory + Procurement + Logistics) are faster than sequential single-agent reads. |
| 2026-06-07 | Adopt LangChain ChatModel as LLM integration layer; introduce ModelRegistry for role-based model selection | Eliminates manual JSON parsing (`_json_obj`/`LLMResponseParseError`) via `with_structured_output()`; encapsulates provider-specific config (Ollama `think=False`) in factory. `LLMClient` protocol retained until all callers migrated. ADR: `docs/adr/2026-06-07-langchain-chatmodel-migration.md` |
| 2026-06-06 | MVP routes all non-chat intents to ControlAgent only — all legacy domain/cross-domain runtime agent roles removed from `VALID_AGENT_ROLES`; `DOMAIN_AGENT_ROLES = {"control"}`, `CROSS_DOMAIN_AGENT_CLASSES = {}`. Per DESIGN.md: SessionOrchestrator delegates every supply chain query to ControlAgent; Specialist Agents are Level 2 (Skill files) in MVP, not runtime units. |
| 2026-06-06 | Playwright tests revert to `page.route()` mock SSE (P44 reverses P37 real-Ollama approach) | `make test-playwright` took 40+ minutes with real Ollama — unacceptable for a quality gate. Mock SSE interceptors reduce the suite to under 2 minutes. Trade-off: tests no longer validate real LLM behavior, but UI component behavior is fully covered. Real Ollama smoke test is limited to `live_trace_verify.spec.ts`. |
| 2026-06-07 | Add 80-character minimum-length guard in `AgentRuntime.run()` to reject degenerate LLM responses before they reach the UI | Two consecutive "Based" / "…However," truncated responses were confirmed in LLM-as-a-Judge sessions (root cause: `model_limitation`). The guard raises `RuntimeError("Degenerate LLM response: …")` before `_output_builder` is called, so the caller can surface an error bubble instead of a one-word stub. `max_tokens` stub defaults raised from 4096 to 8192 to reduce token-exhaustion probability for Ollama quantized models. Token-saturation WARNING log added for observability. |
| 2026-06-10 | Full refactoring programme planned as P65–P70; production infra code explicitly preserved | User decision: `infra/terraform/`, `infra/databricks/`, `packages/lakehouse/`, `AcaJobsRunner`, Celery worker, and `celery`/`redis` dependencies stay untouched (future Azure deployment kept open) even though none are exercised by the current local dev stack. Refactoring targets application-code waste only: dead agent classes (15 files unreachable since P38/P45 — `VALID_AGENT_ROLES == {"control"}`), degenerate multi-agent routing modes, tool registry/allowlist drift, unused frontend modules, dependency/config hygiene, and TASKS.md archive. ADR for routing collapse required before P66 execution. |
| 2026-06-10 | Autonomy Loops programme P71–P73: goal evaluation loop (one bounded refinement + intent re-route), grounded verification (reconnect dead revision path behind LLM groundedness verdict), feedback learning loop (decision_log.outcome fed by UI feedback, annotated in context injection) | The system was a single-pass pipeline; SessionGoal was never constructed, the self-correction path in runtime.py was unreachable, and message feedback was a dead-end signal. All changes additive (SessionResponse optional field, nullable column); LLM budget bounded and fail-open for local 12B models. Deferred: cross-turn agenda, prediction-vs-actuals learning. ADR: docs/adr/2026-06-10-autonomy-loops.md |
