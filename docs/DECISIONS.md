# DECISIONS.md

Lightweight daily log of key design decisions.

| Date | Decision | Rationale |
|---|---|---|
| 2026-06-02 | ~~Do not adopt LangGraph at this time~~ **SUPERSEDED** — see entry below | Superseded by 2026-06-02 LangGraph migration decision. |
| 2026-06-02 | Adopt LangGraph==1.2.4 with `langgraph-checkpoint-postgres` as execution state layer | P1–P8 complete; domain logic stable. Two requirements confirmed inevitable: session resumption (checkpoint) and complex orchestration (DAG + HITL). Option A chosen: LangGraph standard checkpointer as source of truth; `approvals`/`jobs` tables retained as audit logs only. `interrupt()` nodes must have zero DB side effects (re-run-on-resume rule). Public Protocols (`LLMClient`, `Tool`, `Orchestrator`, `Specialist`) unchanged. Full rationale in docs/adr/2026-06-02-langgraph-migration.md. Tracked as P9 (T-063–T-075). |
| 2026-06-02 | Remove stub candidate fallback in `_rank_candidates` immediately | Prohibited by AGENTS.md: "smart stubs that approximate real behavior instead of conforming to the schema contract." When `simulation_optimizer` returns no candidates, raise an explicit error rather than synthesizing MOQ-multiple placeholders. Tracked as T-001. |
| 2026-06-02 | Replace SHA-256 fake embeddings with a real embedding API call | `_make_embedding()` in `packages/memory/__init__.py` generates deterministic hash-based vectors with zero semantic similarity — a smart stub that violates AGENTS.md. Target: Anthropic or OpenAI `text-embedding-3-small`. Requires ADR before changing `MemoryStore` public interface (dimension changes from 192 to 1536/3072). Tracked as T-003. |
| 2026-06-02 | Adopt 3-block prompt caching pattern from agentic-system-mvp | Split system message into: (1) static base prompt with `cache_control: ephemeral`, (2) schema context with `cache_control: ephemeral`, (3) dynamic context without cache. Reduces input token cost without changing public interfaces. Applicable to `AgentRuntime.run()` in `packages/agent/runtime.py`. Tracked as T-008. |
| 2026-06-02 | Adopt LLM cost persistence: write per-call usage to `llm_usage` table | `BudgetGuard` in `packages/agent/llm/__init__.py` is in-memory only and resets on restart. Add `llm_usage` table and persist model, tokens, cost, and role per LLM call. Enables per-session and per-role cost analysis. Does not change public interfaces. Tracked as T-009. |
| 2026-06-02 | T-025 `/files` endpoint lives in `jobs.py` router, not a separate router file | All generated files are accessed in the context of jobs; a separate router would fragment a tightly coupled resource. No ADR required — no public interface Protocol changes. |
| 2026-06-02 | Mock mode activated via `MOCK_LLM=true` env var (server-side only); no UI toggle | Server-side env var is the only safe activation point: a UI toggle could accidentally disable LLM calls in production if the toggle state leaked across sessions. The `LLMClient` Protocol is unchanged — `ScenarioStubClaudeClient` implements the same interface. No ADR required (no public interface change). Tracked as P8 (T-059–T-062). |
| 2026-06-02 | Fix DAG execution to parallelize independent nodes with asyncio.gather | `run_dag_execution()` in `packages/agent/orchestrator/planning.py` processes ready nodes sequentially in a `for` loop, defeating the purpose of the DAG. Replace with `asyncio.gather()` over all dependency-free nodes. Preserves existing public interfaces. Tracked as T-002. |
| 2026-06-03 | Adopt TanStack Query v5 as Web UI server state layer; standardize on `features/<domain>/api.ts` + `features/<domain>/hooks.ts` pattern | All 10 non-SSE pages use ad-hoc `useEffect + fetch` with no AbortController — causing React 18 Strict Mode double-fetch and scattered, inconsistent API code. TanStack Query deduplicates in-flight requests (fixes double-fetch), provides a central invalidation cache, and normalises loading/error state. Package already installed (`^5.50.0`). SSE streaming (`ChatStateContext`) excluded. No Python/public interface changes. Full rationale in docs/adr/2026-06-03-tanstack-query-web-ui.md. Tracked as T-076–T-079. |
| 2026-06-03 | `packages/schemas/sse_events.py` is SSoT for SSE event schemas; `packages/schemas-ts/src/sse-events.ts` is auto-generated via `make codegen` (`scripts/generate_sse_schemas.py`) | Hand-maintaining two files in sync was the root cause of recurring "Invalid SSE event received" errors. Codegen script uses Pydantic v2 model introspection to derive Zod schemas; `JobFile` nested model added so `files` field generates `z.array(JobFileSchema)` instead of `z.array(z.unknown())`. `make codegen` also runs `tsc --noEmit` as a gate. App Builder SPEC updated to require `make codegen` after any `sse_events.py` change. |
| 2026-06-03 | Replace clarification flow (T-019) with proactive AskUser mechanism | Clarification was triggered when intent classification returned `"chat"` with no goal — a false positive for non-English queries and unhelpful even when correct (English-only hardcoded message, round-trip overhead). The new AskUser triggers after intent is confidently classified as analytical (`domain_analysis`, `cross_domain_analysis`, `decision_support`) and detects ONE missing critical parameter before planning. No state tracking needed — the LLM reads conversation_context to detect already-answered questions. `SessionResponse.mode` uses `"direct_chat"` (no public interface change). New SSE event type `ask_user_required` added to schemas. Tracked as T-083–T-085. |
| 2026-06-03 | ~~AskUser uses soft-completion (LLM reads conversation_context)~~ **SUPERSEDED** — see P13 ADR | Soft-completion is fragile: second LLM call must correctly detect the answer from free-text context; misreads cause the question to repeat. Full rationale in docs/adr/2026-06-03-ask-user-interrupt.md. |
| 2026-06-03 | Migrate AskUser to LangGraph `interrupt()`: `prepare_ask_user` + `wait_for_answer` nodes | Typed `Command(resume={"answer": "..."})` injection replaces LLM-based context parsing. Intent state preserved in checkpoint across question/answer round-trip. Adds `answer_ask_user(session_id, answer)` to `Orchestrator` Protocol (ADR required — written). `interrupt()` node has zero DB side effects (P9 rule). Foundation for mid-execution ask_user in P14. Tracked as P13 (T-090–T-099). |
| 2026-06-03 | Remove `Tool.requires_approval` from public Protocol | Audit confirmed no production code reads this field after `safety_level` migration (T-018). All routing uses `safety_level` exclusively. ADR: `docs/adr/2026-06-03-remove-tool-requires-approval.md`. Tracked as T-117. |
| 2026-06-03 | Remove `SessionState.clarification_round` | Field is set but never read. Superseded by LangGraph `interrupt()` mechanism (P13). No ADR required (not a public interface). Tracked as T-118. |
| 2026-06-03 | Text streaming via `text_delta` SSE: `run_direct_chat` + `_synthesize_response` switch from `complete()` to `stream()`; emit `text_delta` SSE per token; frontend appends incrementally; `done.reply` is fallback only. `ClaudeClient.stream()` bug (`data=str(event)`) fixed to use Anthropic SDK `text_stream`. No public interface changes. Tracked as P15 (T-109–T-116). |
| 2026-06-03 | Agent node cards progress display is pure frontend — no backend changes needed | All required SSE events (`agent_started`, `agent_completed`, `tool_started`, `tool_completed`, `execution_mode_selected`, `plan_created`) are already emitted. `ChatStateContext` will be extended with `agentNodes: AgentNodeState[]`. Cards collapse to a one-line summary after `done`; `agentNodes` resets on next send. No public interface changes; no ADR required. Tracked as P14 (T-100–T-108). |
